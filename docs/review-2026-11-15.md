# Review of 2026-11-15: the plan

What the review of the whole repository found, and the order to fix it
in. Each step is a pull request of its own, and arrives with its gate: a
test that fails before the fix. A step that changes how the system runs
records it in [architecture.md](architecture.md) first; one that changes
the language, in [adt81.md](adt81.md) first.

A box is ticked when its pull request is merged. This page is deleted
when every box is.

How the findings were established: "reproduced" means a program or a
request showed it on the built binary; "read" means it follows from the
code and was not run.

## What held

Nothing to do here; it is what the steps below must not break.

- The VM and the reference agreed on 6000 mutated corpus programs and
  about 150 written by hand, but for one error's order (step 8).
- The lexer, the parser and the checker never panicked on 10 000 mutated
  inputs.
- `crates/hbds-maps`: split, merge and borrow walked by hand, nothing
  found.
- The journal on the paths its tests take: a torn tail, the rename and
  the directory's sync in compaction, the grouped thread's order.
- No external crate, and the engines' dependency rule holds.

## The steps

### 1. A daemon whose executor dies, dies

- [x] Today nothing watches the executor's thread
  (`crates/hbds-daemon/src/lib.rs:360`): after a panic the process stays
  up and answers `200 OK` with empty bodies, and systemd's
  `Restart=on-failure` never fires. Reproduced two ways: a pace factor of
  `1e-30` (`Duration::from_secs_f64` at line 938), and a malformed A-code
  unit.
- [x] `Durable::wait` (`crates/hbds-journal/src/lib.rs:342`) wakes on
  failure or progress only: if the journal's thread panics, waiters block
  for good. Read.

Fix: a panic on the executor or on the journal's thread ends the process
with an error, so that the service restarts from the journal. The pace's
factor and a far hold are checked before they reach `Duration`.

Decided on 2026-11-15: exit, rather than catch the panic per turn and
refuse the statement. After a panic in the middle of a statement the
store in memory is suspect, the journal is not. Recorded under decision
3.

Gate: in `tests/daemon.rs`, a session that makes the executor panic; the
daemon's process ends, and a restarted one serves the store.

This step comes first because it turns every panic below from a wedged
daemon into a restart.

### 2. The sequencing set is part of the transaction

- [x] ACTIVATE, CANCEL, KILL and DELAY change the live set directly
  (`crates/hbds-vm/src/lib.rs:2851`, and the reference likewise); a
  rollback restores the store and not the set. Reproduced:
  - a refused statement keeps its ACTIVATE: an object created and
    activated in an ACTION whose statement a COND then refuses stays
    scheduled, and the kernel panics dispatching it (line 1401); with an
    existing process, the process runs after a statement that was
    refused;
  - HYPOCHAV's rollback (`crates/hbds-rules/src/lib.rs:453`) keeps its
    hypotheses' activations: `call hypochav` creating and activating a
    process, then `hold for 5`, panics standalone.

Fix: the set is saved at `begin()` and at each savepoint and restored
with them, or rebuilt from the store's saved text on refusal. The dialog
engine is the model: its state is store objects, and it has no such
hole. Recorded under decisions 5 and 7.

Gate: corpus programs for the two cases, on both engines; a daemon test
where the refused statement's process never runs.

### 3. PURGE leaves nothing behind

- [x] Purging a class does not reach what refers to it
  (`crates/hbds-gtad/src/lib.rs:1097`): other classes keep it in `hyper`,
  and objects keep their values for its inherited attributes. Reproduced:
  `verify()` reports a dangling object attribute, and compaction writes
  changes for an attribute that no longer exists.
- [x] `next` is derived from the surviving ids (lines 840 and 2082), so
  after a purge, a compaction and a reopening, new a.d.t. take purged
  ids. Reproduced: a new class silently became another's hyperclass. The
  daemon's own compaction triggers it.
- [x] Unchecked `map[&id]` on ids that can be purged or rolled back
  panic. Reproduced: CHAV when a rule purges another still on the agenda
  (`crates/hbds-rules/src/lib.rs:440`, and `react` at 706); a process
  activated, destroyed and purged, then HOLD (`body()` in both engines);
  `visible()` on a stale link (`crates/hbds-gtad/src/lib.rs:1295`).
- [x] Values holding a reference to a purged a.d.t. stay as they are.

Fix: purge cascades (hyperclass membership, inherited attributes'
values, prototypes and structures); the journal carries `next`, in a
change of its own that compaction writes; lookups by id in the rules,
the scheduler and `visible()` answer "gone" instead of indexing.
Decided on 2026-11-15: a stored reference to a purged a.d.t. stays as
written, and following it is a runtime error naming it; purge is not
refused, and rewrites no value. Recorded in [hbds.md](hbds.md).

Gate: `verify()` checks `hyper`, associations and modalities; the gtad
random test also calls `set`, `assoc`, `set_property` and `hold_to`, and
purges; a journal test that purges, compacts, reopens and creates.

### 4. The journal stops at its first failed write, in both modes

- [x] The synchronous journal (`crates/hbds-journal/src/lib.rs:63`)
  neither truncates nor stops after a failed write. Reproduced with a
  file size limit: the next commit lands after the torn bytes, and the
  store no longer opens. Decision 5's rule holds for the grouped journal
  only.
- [x] A kept transaction with no change writes a bare `commit` and syncs
  (line 130). Reproduced.
- [x] Outside a transaction, a change the recorder refuses still launches
  its reflexes (`crates/hbds-gtad/src/lib.rs:654`). Read.

Fix: on a failed write the file is truncated to its last commit and the
journal refuses what follows; an empty transaction writes nothing.

Gate: journal tests for a writer failing in the middle of a transaction,
a last line cut short, the lock refusing a second opening, a stale
`journal.new`, and compaction refused while a step is held.

### 5. A-code is verified when it is loaded

- [x] `Unit::read` (`crates/hbds-acode/src/lib.rs:926`) checks the syntax
  only. Reproduced: a unit of the one instruction `load 7` panics `exec`
  (`crates/hbds-vm/src/lib.rs:915`); so do a jump out of the code, a call
  to a module that is not there, and a stack underflow (lines 884, 1593,
  2257). `exec` and the daemon take A-code from files and clients.
- [x] Restored fibers are taken as written
  (`crates/hbds-vm/src/saved.rs:274`): a damaged journal line panics
  later, in the loop. Read.
- [x] Code kept in the store is compiled against the last unit loaded and
  cached by its text (`crates/hbds-vm/src/saved.rs:155`): a COND that
  calls a function may bind to another unit's after a restart. Read; to
  reproduce before fixing.

Fix: a verifier run by every loader: slots, jump and call targets within
bounds, the stack's depth consistent along every path, each module ending
in a return. A fiber is checked against its unit when restored. Recorded
under decisions 1 and 10.

Gate: a test that mutates the corpus's A-code a few thousand times; each
mutant is refused or runs, none panics.

### 6. Limits, where there are none

Each ends today in an abort or a panic; each becomes an error with a
position.

- [x] JSON nesting (`crates/hbds-http/src/json.rs:124`): 200 000 `[` in a
  `POST /pace` abort the daemon. Reproduced.
- [x] Nested `CALL CHAV` in a rule (`crates/hbds-rules/src/lib.rs:444`):
  overflows the stack, on both engines and in the daemon. Reproduced.
  The limit of 64 that ACTIONs have fits.
- [x] Call depth: endless recursion eats the memory on the VM
  (`crates/hbds-vm/src/lib.rs:876`) and overflows the reference's stack
  (`crates/adt81/src/interp.rs:232`); depth 200 000 runs on one and
  aborts on the other. Reproduced. One limit, the same on both.
- [x] Parser nesting (`crates/adt81/src/parser.rs`): 100 000 parentheses,
  or as many terms in one sum, abort `check`, `run` and `fmt`.
  Reproduced.
- [x] Array sizes (`crates/hbds-vm/src/lib.rs:2091`,
  `crates/adt81/src/interp.rs:682`): `VECTOR [1:9223372036854775807]`
  passes `check` and panics; in release the product of the dimensions
  wraps. Reproduced.
- [x] Powers (`crates/hbds-values/src/lib.rs:450`): a Gauss integer or a
  quaternion to the power n multiplies n times; `q ^ 300000000` took 45 s
  in debug. Square and multiply. Reproduced.
- [x] `i64::MIN` (lines 442 and 448) and Gauss products (line 377): a
  panic in debug, a wrong number in release. Reproduced in debug.
- [x] A matrix product with an empty dimension (line 769) indexes out of
  bounds. Reproduced at the API; a program reaches it with two matrices
  declared without bounds.
- [x] HTTP and WebSocket reads (`crates/hbds-http/src/lib.rs:33`, 47 and
  295): no cap on a line, on the headers, on a fragmented message; no
  read timeout, a thread a connection. Read. Also there: a ping in the
  middle of a fragmented message drops the fragments (line 288), and the
  pong is written from the reader's thread while the writer writes
  (`crates/hbds-daemon/src/lib.rs:598`).

- [x] A loop that passes no statement never ends its turn
  (`crates/hbds-vm/src/lib.rs`, `run_fibers`): a turn ends, and the
  budget is counted, at a `stmt` only. The compiler puts one in every
  loop; a client's A-code need not, and the verifier lets it: one
  `jump` to itself holds the executor for good, and a kill is never
  read. Found on 2026-11-15, writing step 5's test, which counts
  instructions to end. Decision 3 has the limit ("a statement over a
  limit is refused whole"); it is not built. Read.

The limits chosen, each recorded where its decision is: JSON 64 deep;
CHAV 64; calls 1000; statements 64 deep and an expression's tree 256
high; an array 16 777 216 cells; a head 64 KiB, a message 64 MiB, a
request 30 s between two reads; 100 000 000 instructions without a
statement, in the daemon only.

Gate: a corpus program or a test for each, on both engines where there
are two.

### 7. Clients that do not cooperate

- [ ] A client that vanishes during a READ wedges the executor for good
  (`crates/hbds-daemon/src/lib.rs:225` and 632), and killing its session
  does not help: the kill is never read. Reproduced.
- [ ] No backpressure (lines 483 and 551): a session printing in a loop
  to a client that never reads took the daemon from 6 MB to 681 MB in
  8 s, and killing it freed nothing. Reproduced. The feed to a stalled
  `GET /events` grows the same way.
- [ ] `ui` checks neither `Origin` nor `Host`
  (`crates/hbds-daemon/src/client.rs:70`): a WebSocket opened from
  another origin ran code against the store, a cross-origin
  `POST /pace` was accepted, and any local user reaches the port, past
  the socket's permissions. Reproduced.
- [ ] `--socket` naming a regular file deletes it (lines 343 to 352).
  Reproduced.

Fix: a READ ends when its client's connection does, and a kill reaches a
session that waits; bounded queues: a session that outruns its client is
killed and its client told why, and a feed's subscriber that falls
behind is disconnected, so that the executor never waits on a client
(decided on 2026-11-15, recorded under decision 8); `ui` refuses a
request whose `Host` is not its own address and whose `Origin`, if any,
is not its own; a stale socket is removed only if it is a socket.

Gate: a test in `tests/daemon.rs` for each.

- [ ] RESULT does not convert to the function's declared type

  gives back an integer makes `F(3) / 2` an integer division.
  Reproduced.
- [ ] A numeric variable takes anything that is not a number
  (`crates/hbds-values/src/lib.rs:251`): `n := K ' FIRST` stores a

- [ ] READ stores fuzziness the variable is not declared with: `{1, 2}`

- [ ] Float `+`, `-` and `*` let infinities and NaN through (line 367),

- [ ] `n MOD (-1)` at the smallest integer, and a FOR loop ending at the

- [ ] `/` truncates and MOD is Euclidean: to check against the print.
- [ ] The one divergence found: in unchecked ACTION text, an unknown READ

Gate: a corpus program each.

## Later, not ordered

Debt rather than defects; each waits for the need.

- About 35 functions exist twice, in `crates/adt81/src/interp.rs` and
  `crates/hbds-vm/src/lib.rs`, with their messages: every feature of an
  engine is written twice, held equal by the gate.
- `begin()` and each savepoint copy the associations, the modalities and
  every module's text (`crates/hbds-gtad/src/lib.rs:678`): what decision
  7 removed for the maps. A purge scans all associations (line 968).
- The reflexes' and constraints' watchers scan every reflex or
  constraint against every association at each change.
- State of the reflexes, the constraints and the fibers lives in
  `crates/hbds-gtad`: the crates' graph is cleaner than the coupling.
- The NixOS module: no system call filter, no memory limit, and a store
  or a socket set elsewhere than the default is neither created nor
  writable.
- `src/build.rs`: a built executable cut short runs as the plain
  command, silently.
